# Menu Data Aset (ITB) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Menu web "Data Aset" dengan dua tab (EAM dan Lapangan), kartu semua penyulang, card "Segmen hilang", dan sinkron bulanan file ITB ke sheet master `db_Aset_ITB`.

**Architecture:** Backend Apps Script modul baru `67_AsetItb.js`: fungsi murni (normalisasi, kunci segmen, pemetaan penyulang, gabung upsert) + dua endpoint (`getDataAset`, `sinkronDataAset`) mengikuti pola `63_Gangguan.js`. Web menghitung rekap/kartu di klien dari baris segmen (modul murni `web/src/asetItb.js`, diuji), halaman `DataAset.jsx` mengikuti gaya History Gangguan.

**Tech Stack:** Google Apps Script (VM harness `tests/harness.js`, `node:test`), React + Vite (`web/`), tes `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-02-data-aset-design.md` (mockup: `.superpowers/brainstorm/4869-1793591426/content/data-aset-v3.html`).

## Global Constraints
- Tidak ada `git add` / `git commit` / push sampai Bapak meminta (pohon kerja repo kotor). Catat berkas yang disentuh.
- Hanya STAGING; production tidak disentuh. Versi backend / app TIDAK dinaikkan di rencana ini (versi dinaikkan saat rilis atas permintaan; backend + `pubspec.yaml` + `versi.dart` harus naik bersama).
- File ITB hanya DIBACA. Master tidak pernah menghapus baris otomatis.
- Menu `OPS_DATA_ASET`, platform WEB, awalnya hanya ADMIN (`aksi` UBAH untuk Perbarui).
- Kunci baris: `CXPENYULANG | DESCRIPTION | JENIS_KABEL | UKURAN_KAWAT` dirapikan (huruf besar, spasi tunggal); kunci kembar di satu file diberi akhiran `#2`, `#3`.
- Nilai tetap: awalan keterangan sistem `Tidak ada di ITB ` dan `Konflik gardu: `; `sumber_pemetaan` ∈ `GARDU | SECTION | BELUM | MANUAL`; kategori ∈ `SUTM | SKTM | LAINNYA` (AAAC, AAACS = SUTM; `N2XSEBY - 1 CORE`, `NA2XSEYBY - 3 CORE` = SKTM).
- Header master (urut): `aset_id, kunci, cx_unit, cx_penyulang, penyulang_itb, description, status, endmeasure, jenis_kabel, panjang_hantaran, ukuran_kawat, kategori, penyulang_lapangan, sumber_pemetaan, kode_gardu, keterangan, bulan_itb, diubah_pada` di tab `db_Aset_ITB` file `MASTER_SHEET_ID`.
- Hanya segmen `OPERATING` (tanpa membedakan huruf besar/kecil) dan tidak hilang masuk SUTM/SKTM; status lain = Non-aktif; segmen hilang tidak dihitung di mana pun. Total jaringan = SUTM + SKTM + Non-aktif.
- Panjang tampil kmS 2 desimal, format Indonesia (koma); data tetap 3 desimal.

## Review Focus
1. File ITB kosong / header salah / sheet `Data_Penyulang` tidak ada: sinkron GAGAL sebelum menulis; master tidak boleh menandai semua baris "hilang". (Task 1, Task 2)
2. Sinkron ulang file yang sama: nol tambah, nol ubah, master identik (idempotent). (Task 1)
3. Koreksi manual Bapak (`penyulang_lapangan` dengan sumber `MANUAL`, `keterangan` bebas) tidak ditimpa sinkron; segmen hilang yang muncul lagi dipulihkan (keterangan sistem dikosongkan). (Task 1)
4. Panjang desimal berpoin ITB (`0.10`, `26.77`) terbaca benar, bukan ribuan; panjang kosong / `-` = 0. (Task 1)
5. Total jaringan: 880,752 + 9,230 + 1,141 = 891,123 (pola sheet Rekap); penyulang tanpa baris tidak muncul; segmen `BELUM` tidak masuk kartu Lapangan. (Task 3)
